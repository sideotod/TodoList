# TodoList Figma 화면 감사

## 범위와 한계

- Figma 파일 `TodoList`의 `01 · 홈 — 월간 할 일` 페이지에서 핵심 데스크톱 화면 11개를 이번 감사 중 새로 캡처했다.
- 화면 크기는 모두 1000 × 780이다. 캡처 이미지는 이 폴더에 저장했다.
- 파일 내 프로토타입 반응(reaction)을 읽어 화면 연결을 확인했다. 연결은 두 개뿐이며, 둘 다 `Dim overlay` 노드로 `SCROLL_TO`한다. Figma 웹 미리보기는 빈 화면으로 열려 실제 클릭 동작은 관찰하지 못했다.
- 이 페이지에는 모바일 프레임이 없다. 사용자가 모바일 앱은 후속 작업으로 지정했으므로 이번 데스크톱 범위의 결함으로 보지 않는다. 스크린샷만으로 키보드·스크린 리더 동작이나 전체 접근성 준수 여부를 판단하지 않았다.

## 감사 결과

### 우선 수정 권장

1. **프로필의 이동 목적 화면 누락** — `프로필 편집`, 이메일, 비밀번호 변경, 시간대, 주 시작일은 이동/변경 affordance가 있지만 목적 화면이나 팝오버 상태가 없다.
2. **Figma 프로토타입 흐름 미완성** — 11개 화면에서 프로토타입 연결은 두 개뿐이다. 두 연결 모두 정렬 모달 안에서 `Dim overlay`를 목적지로 지정해 실제 다음 화면을 확인할 수 없다. 주요 메뉴·저장·닫기·탐색·편집 흐름을 검증하기 어렵다.
3. **추가 메뉴의 항목 불일치** — `04 · Add menu`에는 `새 할 일`, `새 일정`, `디데이 정렬` 세 항목만 있지만 `03 · Add menu — D-day sort popup` 배경에는 `선착순 신청`, `기간 내 할 일`까지 다섯 항목이 보인다. 어느 목록이 현재 기준인지 정하고 한 메뉴로 합쳐야 한다.

### 사용성·접근성 위험

- 우측 상단 세 줄 아이콘은 컴포넌트 이름상 `설정 메뉴`지만 열린 메뉴는 작업·일정 추가와 정렬을 제공한다. 아이콘의 용도를 표시하고 메뉴 항목을 일관되게 만드는 편이 좋다.
- D-day 정렬 화면은 드래그를 안내하지만 카드에 잡을 위치나 드래그 핸들이 보이지 않는다. 긴 목록, 선택 상태, 순서 저장·취소 결과도 화면만으로 알기 어렵다.
- 월간 홈은 작업이 있는 날짜만 보여 준다. 선택한 날짜에 할 일이 없을 때, 데이터가 없을 때, 불러오는 중일 때의 안내가 없다.
- 기간 입력 화면 두 개가 모두 `새 일정`이라는 제목을 쓴다. 일반 일정 생성과 기간형 D-day 생성을 구분하기 어렵고, `종료 미정`을 켠 화면과 입력 검증 상태도 빠져 있다.
- 하단 탐색은 아이콘만 표시하고, 추가 버튼과 체크박스도 작다. 실제 구현에서 접근 가능한 이름, 키보드 포커스, 충분한 터치 영역을 확인해야 한다.
- ICS 가져오기는 사용하지 않기로 결정했다. 가져오기 진입점과 importer 코드를 제거했으므로 이 흐름은 현재 제품 범위에서 제외한다.

위 항목은 Figma 원본을 캡처한 시점의 감사 결과다. 이후 사용자 결정을 구현에 반영했다.

## 권장 순서

1. 메뉴 상태를 한 목록으로 정리하고 각 항목의 도착 화면을 지정한다.
2. 프로필 편집/변경 상태를 추가한다.
3. 빈 상태, 입력 오류, 저장/취소 결과, 종료 미정 상태를 보완한다.
4. 데스크톱에서 아이콘 버튼의 접근 가능한 이름·클릭 영역·키보드 포커스 표시를 정의한다. 모바일 화면 구성은 후속 범위다.
5. 주요 버튼부터 Figma 프로토타입 연결을 추가해 홈 → 작업/일정/기간 생성 → 저장 → 상세/정렬 흐름을 클릭으로 검증한다.

## 사용자 결정과 구현 반영

- 우측 상단 아이콘의 접근 가능한 이름은 `메뉴`로 정했다. 메뉴 항목은 다섯 가지 동작으로 통일했다.
- 기간 정렬은 데스크톱에서 항목을 0.3초 누른 뒤 끌 수 있다. 잡은 항목에 그림자와 이동 표시를 주고, 위아래 버튼도 남겨 키보드와 클릭으로도 조정할 수 있다. `저장`은 홈 순서를 반영하고 `취소`는 임시 순서를 버린다.
- 선택 날짜에 작업이 없으면 `등록된 할 일이 없습니다.`를 표시하고, 진행 중인 기간이 없으면 `진행 중인 기간이 없습니다.`를 표시한다. 계정 저장소를 준비하는 동안은 별도 로딩 화면을 쓴다.
- 기간형 항목은 `신청 기간`과 `제출 마감`으로 구분한다. 신청 기간은 시작 시점을 기준으로 카운트다운하며 종료 시각은 선택 사항이다. 제출 마감은 종료일을 필수로 받고, 시작일과 시작 카운트다운은 선택 사항이다. 일반 일정은 별도의 `고정 일정` 유형이다.
- 아이콘 탐색의 링크 이름, 포커스 표시와 44px 클릭 영역, 36px 추가 버튼을 확인했다. 데스크톱 앱의 밀도를 유지한다.
- ICS 가져오기 UI와 importer 백엔드는 필요하지 않다는 결정에 따라 제거했다. `ical.js` 의존성과 ICS 전용 API, parser, 테스트, IndexedDB 기록 저장소를 삭제했다. DB 업그레이드 시 대기 중인 일반 초안은 보존하고 전용 기록만 제거한다. 기존에 가져온 일정은 원본 메타데이터를 읽을 수 있도록 호환성을 유지하며, 데이터 백업은 `JSON 백업 다운로드`로 제공한다.
- 정렬 창, 항목 편집 창, 전체 기간 창, 동기화 충돌 창, 메뉴는 바깥 클릭으로 닫힌다. 정렬과 편집 창은 Escape 키도 지원한다.

## 이번 데스크톱 구현에 반영한 내용

- 홈 메뉴를 작업 추가, 일정 추가, 디데이 정렬, 선착순 신청 기간, 기간 내 할 일로 통일했다. 각 항목은 해당 입력 화면 또는 정렬 창을 연다.
- 디데이 정렬은 위/아래 버튼, 취소/저장, 키보드 초점 이동을 제공하며 순서는 이 기기의 브라우저에 저장한다. 계정 간 동기화는 하지 않는다.
- 기존 프로필 편집·이메일·비밀번호 버튼은 구현 가능한 계정 기능이 없어서 새 화면에 두지 않았다. 대신 실제 동작하는 주간 시작일·시간대·알림·백업/복원을 제공하고, 미리보기 계정은 읽기 전용으로 표시한다.
- 월간 홈과 주간 캘린더를 1000 × 780 데스크톱 프레임과 840px 콘텐츠 폭에 맞췄다. 모바일 UI는 이번 범위에 포함하지 않았다.
- 앱의 주요 메뉴, 기간 정렬 저장, 캘린더/설정 화면을 로컬 미리보기에서 확인했다. Figma 원본 프로토타입 연결 자체는 수정하지 않았으며, Figma 웹 미리보기는 현재 빈 화면이라 실제 클릭 연결은 확인하지 못했다.
