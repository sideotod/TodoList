## 2026-10-07 우측 하단 펼침·캘린더 오버레이·완료 하위 항목

사용자가 선택한 두 번째 시안의 얇은 구분선과 펼침 손잡이를 computer use로 기존 홈 `84:467`과 펼침 `84:584`에 반영했다. 상단 `기간 일정`·`전체 5개`는 제거된 상태를 유지한다. 접힌 홈에는 기존 3개 카드만 표시하며, 하단 추가 카드의 일부나 흐릿한 미리보기를 두지 않는다. 두 프레임은 1000×780, 콘텐츠 폭은 840px다.

- 접힘: 카드 영역 `(80,96)`의 첫 세 카드 아래에 얇은 연보라 선을 두고, 우측 하단 `(890,170) 30×20` 손잡이에 아래 chevron을 배치했다. 화면에는 전체 보기 문구·개수·배지를 추가하지 않았다.
- 펼침: 같은 위치에서 카드 5개가 중복 없이 3+2로 보인다. 약 840×178의 흰 불투명 패널만 월간 영역 위에 배치해 캘린더 상단을 가린다. 캘린더·할 일·하단 탐색의 위치와 크기는 접힘 상태와 동일하다. 위 chevron은 패널 우측 하단 `(890,254)`에 있다. 캘린더를 축소하거나 아래로 밀지 않는다.
- Figma Prototype 패널에서 아래 chevron `181:1074` → `84:584`, 위 chevron `181:1083` → `84:467`을 클릭, Smart Animate, ease-out(`천천히 나감`), 220ms로 연결했다. 실제 1000×780 프레젠테이션에서 화살표를 눌러 펼침·접힘 왕복을 확인했다. 진행 막대는 기존 상태 표시를 유지한다.

### 앱 반영과 남은 검증

이번 추가 화면은 Figma 설계다. 새 프레임의 하단 탐색·추가 메뉴·팝업 간 프로토타입 연결과 앱 코드 반영은 남아 있다. 세로 스크롤은 위 두 영역만 Figma 미리보기에서 확인했으며 실제 저장, 키보드 또는 계정 변경을 검증했다고 주장하지 않는다. 앱의 현재 설정에는 로그인 모드별 차이가 있으므로 예시 프로필·비밀번호 행을 실제 제공 기능으로 그대로 옮기지 않는다.

앱은 전환 전 `114:*` 기준의 구현을 유지한다. 새 홈의 보드 y96, 월간 제목의 위치, 520/296px 영역 폭, 3개 라벤더 카드, 220px 추가 메뉴 및 입력 내부 392px 폭 등은 새 기준에 맞춰 후속 반영해야 한다. 실제 시각/기간 진행률 계산과 기존 저장값·편집값은 계속 앱의 도메인 규칙을 따른다. 새 설계 반영 때도 시작/종료·countdown·하위 할 일·완료·시간대/DST·알림·메모·링크, 유형 고정, 포커스·Escape·취소·저장의 기존 계약을 유지한다.

이 설계 단계에서 제품 코드는 변경하지 않았고 새 프로덕션 의존성·Firebase 변경도 없다. 마지막으로 3001 프리뷰 서버의 HTTP 200 응답과 단일 Figma 페이지 `0:1`을 다시 확인했다. 브라우저 임시 viewport는 원래 크기로 복귀했고 Figma 편집 탭은 유지했다.

프로젝트의 완료 체크리스트에 따라 `pnpm typecheck`, `pnpm lint`를 재실행해 종료 코드 0을 확인했다. `pnpm test`는 unit 16개 파일/213개 테스트가 통과한 뒤 `java -version` 실패로 Emulator 시작 단계에서 종료 코드 2로 중단됐다. 전체 테스트가 통과했다고 기록하지 않는다. JDK/Firebase 설정은 변경하지 않았다. 아래 build/preview E2E 결과는 전환 전 코드 변경의 이력이며 새 Figma 화면의 구현 검증이 아니다.

- 840px 콘텐츠 폭과 좌우 위치 `(80…920)`, 흰 배경, 테두리 없는 카드, 3열의 가로 폭·간격, 우측 상단 햄버거 아이콘, 하단 탐색 `(80,710) 840×52`는 기준과 일치한다.
- 두 화면 모두 1000×780 문서 안에서 가로/세로 overflow가 없다. 하단의 큰 공백은 Figma에도 있으므로 결함으로 보지 않는다.
- 기간 입력의 변경 전 실제 bounds는 560×702다. Figma는 440×304 구성요소 안에 410×34 필드를 사용하므로 외곽 크기와 정보 밀도가 다르다. 날짜·상태 예시의 차이는 fixture와 캡처 시각에 따른다.
- 캡처는 시각 배치 증거다. VoiceOver/키보드 전 경로, 모든 창 크기, 시스템 알림은 이 문서의 캡처만으로 판정하지 않는다.

## 수정 뒤 재검수 기준

같은 1000×780 프레임에서 홈·오버레이·메뉴·기간 입력을 다시 캡처하고 다음을 확인한다.

1. 월 헤더와 하단 내비게이션의 기준 좌표를 유지한다.
2. 기간 보드, 월간 grid, 선택 날짜 제목, `+` 위치가 표의 Figma 좌표에 맞는다.
3. 날짜 열·글자·주말 라벨·선택 날짜·일정 점의 크기와 색이 Figma와 맞는다.
4. 오버레이가 정확한 위치에 떠서 기존 화면을 덮고, 세 열 카드가 잘리지 않는다.
5. 메뉴 bounds와 두 입력 항목의 밀도가 Figma와 맞으며 편집/닫기 키보드 동작이 유지된다.
6. 수정 후 PNG를 이 폴더에 추가하고 이 문서를 읽어 불일치·잘림·겹침을 다시 검토한다.

### 남은 차이와 원본 상태

- Figma 신청 입력 구성요소는 440×304이며 필드만 간결하게 표시한다. 구현의 기본 높이 463px에는 날짜/시각 모드, 카운트다운 조절, 두 펼침 버튼, 닫기 버튼이 포함되어 높이가 더 크다. 1:1 복제로 판정하지 않는다.
- Figma 주간 원본의 `10월 4일–10일` 범위와 `5–11` 날짜 열, 첫 요일, `13:00` 이벤트의 약 10:30 위치, 그리드 밖 18/20시 표시는 서로 일치하지 않는다. 앱은 실제 날짜·시각 계산을 사용한다.
- computer use로 열린 Figma 사이트를 확인했지만 `Figma에 연결할 수 없습니다`와 `일부 변경 사항은 Figma가 다시 연결될 때까지 동기화되지 않습니다`가 표시된다. 원본 변경은 저장 완료를 검증할 수 없어 수행하지 않았다. 기존 사용자 편집 내용을 보존했다. 원본의 날짜·요일·이벤트 위치 정정은 연결 복구 뒤 남은 작업이다.
- 최종 새 로드→메뉴→입력→펼침→취소 흐름에서 pageerror·console error·HTTP 400 이상 응답은 0건이었다. 주간 캘린더에는 기존 root HTML의 smooth scrolling 속성 관련 경고 1개가 있다.
