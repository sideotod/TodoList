# 데스크톱 컴포넌트 시스템 설계

작성 기준: 2026-10-05 · 상태: 사용자 승인 · Firebase 동기화 후순위

이 문서는 현재 프론트엔드 구조를 Figma와 한 요소씩 대조할 수 있도록 다시 정의한다. 구현자는 이 문서와 Figma 컴포넌트를 먼저 함께 확인하고, 승인 뒤에만 컴포넌트 단위로 구현한다. 각 단계에서 같은 상태의 Figma와 실행 화면을 비교한다. 기존 데이터 도메인·시간 의미·충돌 보존 계약은 유지하며, 이전 화면 문서와 충돌하는 데스크톱 배치·탐색 결정은 이 문서를 우선한다.

## 제품 방향과 작업 경계

- 첫 검수 목표는 macOS에서 작동하는 작은 데스크톱 화면이다. 먼저 브라우저에서 기능을 확인하고 서버로 미리보기를 제공한다. 사용자가 승인한 뒤 앱 패키징 방식을 정한다. 이 작업 묶음에서는 iOS 레이아웃/설치를 검수하지 않는다.
- 기준 브라우저 창은 `1000×780px`이다. 실제 UI는 가운데 정렬한 최대 너비 `840px`의 작업 공간을 사용한다. 창이 커져도 요소가 커지거나 늘어나지 않고 바깥 흰 여백만 늘어난다. 작은 창에서는 넘침 없이 줄이되 기준 창보다 큰 화면에서 확대하지 않는다.
- 홈은 TodoMate 스타일의 월간 할 일 화면이다. 월간 칸과 선택한 날짜의 일일 할 일이 주 콘텐츠이며, 기간 카드는 위쪽에 최대 3개까지만 둔다. 홈 본문은 기준 창에서 페이지 전체 스크롤 없이 보인다.
- 캘린더는 하단 중앙 아이콘에서 여는 별도 주간 시간표다. 월간 격자를 다시 표시하지 않고, 날짜 열과 시각 눈금으로 고정 일정을 본다.
- 날짜별 할 일은 홈의 `+`로 추가한다. 우측 상단 햄버거는 기간형 항목 생성 메뉴이며 두 종류만 제공한다: 시작 카운트다운이 있는 `선착순 신청`, 시작 카운트다운이 없는 `기간 내 할 일`.
- 하단 바는 홈·주간 캘린더·설정의 아이콘 세 개를 화면 중앙에 배치한다. 아이콘만 보이지만 각 버튼은 접근성 이름, 툴팁, 선택 상태를 갖는다.
- 배경은 흰색이며 시각적 분류는 면 색, 간격, 글자 위계로 한다. 일반 카드 테두리를 두르지 않는다. 떠 있는 기간 목록과 입력 다이얼로그에만 부드러운 그림자를 쓴다.
- 이번 UI 단계에서는 Firebase 동기화를 전제로 하지 않는다. 현재 Firebase 코드를 이 범위에서 제거하지는 않지만, 검수는 `?preview=design`의 브라우저 로컬 저장으로 진행하고 로그인·서버 동기화가 없어도 CRUD·완료·재정렬이 동작해야 한다. 로컬 저장 상태를 동기화 완료로 표시하지 않는다. 기존 repository 경계를 유지해 저장소 교체 가능성을 보존한다.

| 크기 기준 | 목표 |
|---|---|
| 기준 창 / 고정 작업 폭 | 1000×780 / 최대 840px, 가운데 정렬 |
| 홈 기간 카드 | 3열, 카드 높이 약 72px, 열 간격 약 12px |
| 홈 주요 영역 | 월간 달력 약 1.4 : 선택 날짜 목록 1 비율, 열 간격 약 24px |
| 주간 시간표 | 시간 gutter 약 44px, 나머지를 7개 날짜 열로 나눔 |
| 주요 아이콘 | 20–24px 그림, 조작 영역 최소 40×40px; 하단 아이콘은 최소 44×44px 영역 |
| 입력 행/대화상자 | 컨트롤 높이 32–36px, 다이얼로그 폭 최대 480px |
| 글자 | 본문 13–14px, 부가 11–12px, 화면 제목 17–18px부터 Figma에서 조정 |

이 값은 기준 창에서 작은 앱처럼 보이게 할 초기 측정치다. 기존 Figma와 나란히 확인해 수정한 뒤 Figma component property/spacing으로 확정한다. 뷰포트 확대에 반응해 이 값을 비례 확대하지 않는다.

## Figma 작업 계약

현재 흰 배경 Figma 파일의 선택 보드 방향을 유지한다. [선택된 3개 기간 보드](https://www.figma.com/design/o81oyODBLYZuzBAkKcWqgp?node-id=84-467), [기간 확장 오버레이](https://www.figma.com/design/o81oyODBLYZuzBAkKcWqgp?node-id=84-584)를 참고한다. 새 프레임을 그리거나 각 요소의 세부를 조정하는 일은 문서 검토 후 진행한다.

Figma 작업은 `Component system` 페이지를 만들고 다음 순서로 진행한다.

1. 토큰과 기초 요소: 색, 글꼴, 간격, 입력 높이, 아이콘 슬롯, 초점 표시, 그림자.
2. 재사용 컴포넌트: 버튼, 날짜 칸, 일일 할 일 행, 기간 카드, 오버플로 패널, 메뉴, 입력 필드, 주간 시간표 요소, 하단 탐색, 설정 행.
3. 상태 변형: 기본·hover·focus·pressed·disabled·오류·저장 중·완료, 일정 단계별 기간 카드, 드래그 대상.
4. 화면 프레임: 홈 기본, 기간 목록 열림, 햄버거 열림, 두 종류의 기간 입력, 주간 시간표, 전체 기간/완료 내역, 설정.
5. 각 컴포넌트/화면의 인터랙션 연결과 주요 흐름 프로토타입.

아이콘은 Figma에서 확정한 SVG 자산을 내보내 사용한다. 화살표와 햄버거를 문자 글리프로 대체하지 않는다. Figma의 실제 컴포넌트 이름, node 링크, 아이콘 SVG 경로를 각 구현 PR/검수표에 연결한다. 사용자가 이미 바꾼 Figma 요소는 새로 만들지 않고 현재 내용을 확인한 뒤 손댈 요소만 수정한다.

## 화면과 이동 구조

| 화면 | 목적 | 진입 버튼 | 닫기/복귀 |
|---|---|---|---|
| 홈 `/` | 월간 할 일, 선택 날짜 할 일, 임박 기간 최대 3개 | 홈 아이콘 | 해당 없음 |
| 주간 캘린더 `/calendar` | 요일별 종일 항목과 시간 지정 고정 일정 | 하단 중앙 캘린더 아이콘 | 같은 주 선택 상태 유지 |
| 기간 목록 `/calendar?filter=period` | 예정·진행·기간 종료·완료 상태의 전체 기간 관리 | 주간 캘린더의 `기간` 버튼 | 주간 캘린더 버튼 |
| 날짜 미정 할 일 `/tasks` | 날짜를 정하지 않은 일일 task 확인/추가 | 홈의 `날짜 미정 할 일 보기` 링크 | 홈 아이콘 |
| 설정 `/settings` | 시간·주간 보기·알림·로컬 데이터 환경설정 | 하단 설정 아이콘 | 홈 또는 직전 화면 |
| 기간 더 보기 오버레이 | 모든 표시 대상 기간을 급한 순으로 확인 | 기간 섹션 화살표 | 화살표, 바깥 클릭, Escape |
| 햄버거 메뉴 | 두 종류의 기간 항목 생성 진입 | 홈 우측 상단 Figma 메뉴 아이콘 | 바깥 클릭, Escape, 선택 |
| 항목 편집 다이얼로그 | 일일 할 일, 기간 항목, 고정 일정 편집 | 제목·기간 카드·시간표 항목 | 취소/닫기, 저장 후 닫기 |

하단 중앙 캘린더는 월/주 전환기가 아니라 주간 시간표로 바로 열린다. 월간 계획은 홈에 남긴다. `/tasks`는 날짜 미정 할 일을 찾는 보조 경로로 유지하고 하단 바에는 추가하지 않는다. 캘린더에 입력된 고정 수업·미팅은 기간 메뉴에 섞지 않는다.

## 컴포넌트 목록과 동작 계약

모든 행의 `Figma 선행`은 코드 변경 전 해당 구성요소와 상태 변형을 Figma에 준비한다는 뜻이다. UI 구현은 한 묶음이 끝날 때마다 Figma와 기준 창 캡처를 나란히 확인한다.

| ID / 구성요소 | Figma 변형·시각 기준 | 동작·상태 계약 | 검수 |
|---|---|---|---|
| C-01 `DesktopCanvas` | 흰 배경, 가운데 고정 작업 공간, 기준 뷰포트 1000×780, 콘텐츠 최대 폭 840 | 넓은 창에서 콘텐츠 폭을 키우지 않는다. 홈은 외부 스크롤 없이 배치한다. 창이 좁을 때만 내부 세로 스크롤을 허용한다. | 1000×780·1440×1024·2000×1200에서 내용 폭과 중심 정렬 동일 |
| C-02 `HomePeriodBoard` | 3열, 높이·간격 고정, 기간 카드에 테두리 없음 | 급한 순으로 최대 3개를 고정 노출한다. 기간이 적을 때 남는 칸을 늘려 카드 폭을 키우지 않는다. 없음 상태는 짧은 안내로 표시한다. | 0/1/2/3/4+개, 완료 항목 제외와 노출 순서 |
| C-03 `PeriodCard` | 제목, 시작/종료 endpoint, 단일 진행 bar, 우측 요약만 표시. 제목 행과 bar 사이는 약 6px, endpoint는 bar 바로 아래 | 진행률은 시간 경과, checklist는 별도 상태. checklist 0개면 완료 문구를 감춘다. 1개는 `미완료`/`완료`, 2개 이상은 `미완료(남은 수/전체 수)`/`완료`. 시작 전 중복 문구를 카드 바깥에 쓰지 않는다. 부모 완료 조작은 상세에서 한다. | 양 끝 날짜, 진행 단계별 색, checklist 수와 완료/재개방 |

| C-06 `PeriodOverflowOverlay` | 흰 표면·부드러운 외부 그림자, 3열 격자, 캘린더를 덮는 위치 | 열림 시 기본 카드 영역을 포함한 모든 미완료 기간을 한 목록으로 그린다. 홈 레이아웃을 밀지 않는다. 높이는 화면의 70% 이하, 초과 항목만 패널 안에서 스크롤한다. 바깥 클릭/Escape/접기 버튼으로 닫고 마지막 초점을 복원한다. 한 항목을 열면 오버레이를 닫는다. | 겹침/z-index, 아래 콘텐츠 가림, 1·3·4·7개 격자, 포커스 복귀 |
| C-07 `TopActionMenu` | 우측 상단 Figma SVG 햄버거, 짧은 그림자 메뉴 | `선착순 신청 추가`, `기간 내 할 일 추가` 두 항목만 제공한다. 항목 선택 시 정확한 유형이 미리 지정된 편집 창을 연다. 바깥 클릭/Escape로 닫는다. | 메뉴 위치·겹침·두 진입 흐름·키보드 |
| C-08 `DailyTaskAddButton` | 선택 날짜 제목 옆 작은 원형 `+`, 한 종류 버튼 | 현재 선택 날짜가 기본인 하루 할 일 입력을 연다. 기간형/고정 일정 유형 선택을 노출하지 않는다. 저장·취소 후 날짜 선택을 유지한다. | 선택 날짜 전달, 날짜 변경 뒤 기본값, 중복 진입 방지 |
| C-09 `MonthHeader` | 간결한 월 표시와 좌우 Figma SVG 화살표 | 이전/다음 달 이동, 달력 칸에서 날짜를 고르면 선택일 목록을 갱신한다. 새 월의 날짜를 임의로 오늘로 바꾸지 않는다. | 윤년·월말 이동, 선택일·선택 월 동기화 |

| C-11 `SelectedDayTaskList` | 날짜 제목, 세로로 조밀한 할 일 행, 완료 그룹은 하단 | 미완료/완료를 나눠 각각 순서를 유지한다. 완료 체크 시 미완료 그룹에서 빠져 완료 그룹 맨 아래에 추가한다. 체크 해제 시 미완료 그룹 맨 아래에 추가한다. | 체크·해제 이동, 새로고침 보존, 날짜별 독립 순서 |

## 카드 및 입력 필드 규칙

### 기간 보드와 진행 바

- 시간순 임박 정렬은 기존 `selectUrgentHomePeriods` projection 기준이다. 초 단위 countdown tick만으로 읽던 카드의 위치를 옮기지 않는다.
- 홈에는 완료되지 않은 기간 중 최대 세 개만 보여준다. 더 많은 항목이 있을 때만 Figma SVG 화살표를 표시한다.
- 각 카드에는 이름, 기간 시작·끝, bar, 우측 한 줄 요약(남은 시간 또는 checklist 상태)을 둔다. 시작 예정 텍스트나 할 일 추가 문구를 bar 옆·우측 요약에 중복하지 않는다.
- 색은 상태도 전달하되 텍스트/모양도 함께 사용한다. 추천 팔레트: 예정 `#B8A8F4`, 진행 중 `#6E4DF5`, 종료 `#B7B7C2`, track `#E8E8F2`. 기존 흰 배경·라벤더 스타일과 대비를 Figma에서 확인한 뒤 확정한다.
- 시작 countdown은 1일 전 기본 노출, 설정 0–30일이다. 24시간 이상은 `D-N`, 24시간 아래는 시:분, 10분 미만은 분:초다. 정확한 시각 없이 날짜만 있으면 D-N/D-Day로 표시한다. 시작 표시를 끄면 예정 bar는 보여도 카운트다운은 숨긴다.
- 종료된 bar는 회색이며 시간 경과율 100%다. 부모 제출/신청 완료는 시간 경과와 별도고, 상세의 완료 동작으로만 바뀐다. 하위 할 일이 모두 완료여도 부모 완료를 자동 처리하지 않는다.

### 입력 모달

공통 입력: 제목, 시작/끝 날짜 또는 시각, 선택 메모, 저장/취소. 기본 대화상자는 너비 `480px` 이하로 설계하며 긴 화면에서는 모달 안쪽만 스크롤한다. 폼은 제목, 날짜/시각, 기간 checklist 순으로 간다.

`선착순 신청` 폼은 일정 종류를 바꾸는 select가 없다. 시간 지정 시작을 기본으로 권고하되, 게시 공지가 날짜만 제공하면 종일 날짜를 선택할 수 있다. 시작·종료는 시간대 `Asia/Seoul`을 적용한다. 링크는 선택 항목이고 입력해도 별도 네트워크를 호출하지 않는다. 하루 전 기본 시작 표시를 체크해 제공한다.

`기간 내 할 일` 폼은 시작과 종료 기간을 모두 받는다. 시작 카운트다운 옵션은 보이지 않는다. 추가 checklist는 선택 사항이다. 제목·하위 할 일 개수 한도는 기존 domain validation 및 단일 문서 계약을 그대로 따른다.

## 설정 추천안

아래는 기능을 넣기 전에 사용자에게 보여 줄 권고 기본값이다. 사용자가 이 문서를 검토하면서 변경할 수 있다.

| 그룹 | 추천 항목 | 기본값/표현 |
|---|---|---|
| 달력 | 시간대 | `Asia/Seoul`; 날짜만 있는 D-Day 의미를 바꾸지 않는다는 설명 |
| 달력 | 주 시작 | 일요일; 월요일도 선택 가능 |
| 달력 | 시간 형식 | 24시간 |
| 주간 보기 | 표시 시간 | 08:00–22:00; 앞뒤 시간은 그리드 내부 스크롤 |
| 알림 | 전체 알림 | 꺼짐; countdown 표시는 이 스위치와 별개 |
| 알림 | 항목별 사전 알림 | 사용자가 켰을 때만 선택 가능. 초기 브라우저 미리보기는 실행 중 전달 한계를 설명 |
| 데이터 | ICS 가져오기 | 주간 캘린더의 가져오기 진입에서 미리보기 후 반영 |
| 데이터 | JSON 백업/복원 | 로컬 데이터 내보내기와 복원, 복원 전 요약/확인 |
| 계정/동기화 | Firebase 로그인·동기화 | 이 구현 범위에서는 표시하지 않고 후속 단계에서 추가 |

상태 초기값·UI 표기는 기기 로컬 환경설정으로 저장한다. 로그인, Firebase 설정, 클라우드 상태를 이번 화면의 저장 성공과 섞지 않는다. JSON 복원/전체 삭제는 데이터 손실 가능성이 있으므로 요약 및 명시 확인을 거친다. 전체 삭제 설정을 넣을지는 다음 범위 검토 항목이다.

## 기간/할 일/고정 일정 화면 배치 의미

| 종류 | 홈 월간 칸 | 홈 기간 보드 | 주간 종일 레인 | 시간 그리드 | 완료 처리 |
|---|---|---|---|---|---|
| 하루 할 일 `task` | 날짜 점 | 표시 안 함 | 날짜형은 할 일 칩 | 정확한 마감 시각은 얇은 마감 표식(일정 block이 아님) | 홈 목록 checkbox만 |
| 기간 내 할 일 `deadline` | 표시 안 함 | bar와 checklist 요약 | 기간 표식 | 표시 안 함 | 상세의 부모 완료와 개별 checklist 분리 |
| 선착순 신청 `window` | 표시 안 함 | bar와 시작 countdown | 신청 기간 표식 | 표시 안 함 | 상세의 신청 완료와 개별 checklist 분리 |
| 고정 일정 `event` | 표시 안 함 | 표시 안 함 | 종일 일정만 | 시간 일정 | 완료 checkbox 없음 |

주간 시간표의 하루 할 일 chip/마감 표식이 task checkbox와 별도로 상태를 바꾸지 않게 한다. 완료 조작이 가능한 곳은 홈의 일일 할 일 행으로 통일한다. 정확한 마감 task 표식은 기존 timing의 `endAt`을 사용해 실제 시각에 놓는다.

## 기능 수용 기준

1. `1000×780`에서 홈은 앱 이름/검색을 추가하지 않고 월간 할 일, 기간 최대 3개, 선택 날짜 목록, 중앙 하단 바를 보인다. 화면이 커져도 작업 요소 크기는 그대로다.
2. 하루 할 일 추가 버튼은 그 날짜의 일일 task 입력을 연다. hamburger는 두 기간 유형 입력만 연다. 화면 어디에서도 같은 항목 진입을 중복 노출하지 않는다.
3. 기간 카드 화살표는 Figma SVG이며 진행 bar 시작과 정렬된다. 확장 패널은 첫 세 항목을 포함한 전체 기간을 3열로 보이고 캘린더를 덮으며 아래 레이아웃을 밀지 않는다.
4. 확장/축소 모션은 160–220ms, opacity+짧은 translate+scale로 진행한다. 과한 탄성/바운스는 쓰지 않는다. `prefers-reduced-motion`이면 위치 변화 없이 즉시 바뀐다. 닫기 상태에서 초점은 화살표로 돌아간다.
5. 기간 카드 이름·bar·끝점·남은 시간/상태 간격은 Figma spacing token과 일치한다. 기간 양 끝 날짜는 bar 양 끝에 한 번씩만 보인다.
6. 선착순 신청은 시작·종료를 저장하고 설정된 시점부터 시작 countdown을 표시한다. 기간 내 할 일은 시작·종료와 checklist를 저장하지만 시작 countdown 컨트롤/표시를 만들지 않는다.
7. checklist가 없으면 완료 상태 텍스트를 숨긴다. 하나 이상이면 정확한 미완료 수를 표시하고, 전체 완료 후 다시 항목을 추가하면 미완료 상태로 돌아간다. 기간 checkbox를 카드에 중복 추가하지 않는다.
8. 홈의 월간 날짜 변경과 일일 할 일 목록이 함께 움직인다. 완료 checkbox는 체크 즉시 다른 그룹의 맨 아래로 이동하며 재실행 후에도 같은 순서를 유지한다. drag reorder는 미완료/완료 그룹 안에서만 작동한다.
9. 하단 중앙 아이콘은 주간 시간표로 이동한다. 주간 시간표에는 실제 시간 눈금이 있고, 고정 일정 block 클릭 편집과 빈 시간 클릭 추가가 동작한다. 기존 `기간` 진입은 전체 기간/완료 내역으로 연결한다. 하단 설정은 값을 저장하고 새로 열어도 유지한다.
10. 알림은 설정에서 선택 가능하되 기본 꺼짐이다. countdown이 보인다는 이유로 OS 알림을 예약하지 않는다.
11. 메뉴, popover, 다이얼로그, 설정 입력은 마우스와 키보드에서 조작 가능하고 포커스/오류/비어 있음/저장 실패 상태가 Figma와 구현 모두에 존재한다.
12. Figma와 구현 비교 캡처는 `1000×780`에서 홈 기본·오버레이·메뉴·기간 입력 두 종류·주간 캘린더·설정을 각각 남긴다. 1440px 이상 창에서 콘텐츠가 커지지 않는 것도 확인한다.

## 다음 단계 전에 검토할 선택

- 고정 콘텐츠 너비 `840px`와 기준 창 `1000×780px`이 실제 TodoMate 창에서 맞는지.
- 주간 캘린더 표시 범위 기본 `08:00–22:00`, 기본 주 시작 일요일이 맞는지.
- 주간 캘린더에 `오늘` 빠른 복귀 버튼을 둘지. 이 문서는 추가를 권고한다.
- 하단 설정 아이콘을 현재 사람 모양으로 둘지, Figma에 기어 아이콘을 새로 그릴지. 의미를 명확히 하려면 기어를 권고한다.
- 선착순 신청 입력은 시각 지정 기본값으로 할지. 이 문서는 시간 지정 기본, 종일 선택을 권고한다.
- 기간 bar 색상(예정/진행/종료)과 빈 기간 상태 안내 문구가 현재 편집된 Figma와 맞는지.
- 홈에서 완료된 기간은 요약에서 계속 감출지. 이 문서는 기존 urgency projection처럼 감추고 기간 목록/편집 상세에서 확인하는 것을 유지한다.
- JSON 복원/ICS 위치를 설정과 캘린더 중 어디에 둘지. 이 문서는 실제 ICS 실행은 캘린더, JSON 백업/복원은 설정으로 분리한다.
- 기간 checklist 항목의 최대 4개 상한을 제품 흐름에서 유지할지. 데이터·Rules 호환성상 현 상한 유지가 권고다.

## 구현 전 검수 흐름

1. 사용자는 본 문서와 제안 선택 항목을 검토한다.
2. Figma에서 컴포넌트 라이브러리와 각 화면 프레임을 구성/수정한다. 버튼과 각 상태의 인터랙션을 연결한다.
3. Figma 프레임별 PNG와 실제 기준 뷰포트 캡처를 쌍으로 둔다. 텍스트·간격·크기·색·겹침을 표의 acceptance ID와 비교한다.
4. 구현은 foundation → home components → period interactions → weekly calendar → settings → data form의 순서로 진행한다. 각 단계마다 실행 가능한 한 가지 흐름을 보여주고 다음 단계로 넘어간다.
5. 컴포넌트 상태와 수용 기준을 모두 맞춘 뒤 `pnpm test`, `pnpm typecheck`, `pnpm lint`, `pnpm build`, 필요한 E2E를 실행한다. Firebase 작업은 제외한다.
6. 로컬 웹 미리보기를 제공해 사용자가 먼저 macOS에서 확인한다. 사용자의 UI 검토 뒤 네이티브 데스크톱 패키징 단계를 따로 결정한다.

## 현 구현과 새 계약의 차이

2026-10-05 현재 브라우저 캡처/코드에서 확인한 간극은 다음과 같다.

- 홈 요소가 fluid grid로 넓어지는 구조라 작은 데스크톱 작업 공간 계약과 다르다.
- 월간 홈에서 우측 상단 햄버거로 두 기간 유형을 여는 진입이 없다.
- 하단 가운데 아이콘은 현재 날짜 중심 캘린더 route로 이동하며 시간 표시 주간 그리드가 없다.
- 설정 route에 캘린더 표시 선호가 없다. Preview 설정은 로컬 알림만 다룬다.
- 화면 구조는 실제 Figma의 간격과 카드 위계에 맞춰 조정해야 한다. 다만 Figma SVG 자산에는 선택된 chevron과 체크 아이콘 일부가 이미 있다.
- 기존 구현에 드래그 정렬·완료 시 그룹 이동이 있으나, 확대/재실행·그룹 내 순서를 새 기준 창에서 다시 확인해야 한다.

이 목록은 현재 코드를 검사해 얻은 범위 간극이며, 구현 완료나 검증 성공을 주장하지 않는다. 상세 시각 결함과 이전 수정 캡처는 [UI 감사 기록](ui-audit/current-ui-audit.md)을 참고한다.
