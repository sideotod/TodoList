# 데스크톱 UI 감사와 구성요소 동작

기준일: 2026-10-06 · 앱 범위: Firebase 연동 제외 · 비교 창: 1000×780px · 앱 프레임: 840×780px

이 문서는 사용자가 수정한 Figma 화면과 로컬 프리뷰를 같은 크기·시간대에서 대조한 결과, 반영한 수정, 남은 시각 차이를 기록한다. 최신 캡처는 [감사 폴더](ui-audit/current-2026-10-06/)에 저장한다.

## 2026-10-07 우측 하단 펼침·캘린더 오버레이·완료 하위 항목

Figma 홈 `84:467`은 3개 기간 카드만 보여주고 아래 추가 카드 미리보기는 숨긴다. 카드 아래의 얇은 구분선 우측 끝에 아래 chevron 손잡이를 두고, 클릭하면 기존 펼침 화면 `84:584`로 이동한다. 상단 `기간 일정`·전체 개수와 별도 `전체 보기`·`더 보기` 문구는 제거된 상태를 유지한다. 카드 제목은 계속 해당 기간 편집 진입점이다.

펼침에서는 같은 첫 세 카드에 두 카드를 더한 3+2 목록이 흰 불투명 패널 안에 한 번만 나타난다. 패널은 `(80,96)`에서 아래로 확장되어 캘린더 위를 가린다. 캘린더·할 일·하단 탐색은 접힘 상태와 같은 위치·크기를 유지하며 축소하거나 아래로 밀지 않는다. 마지막 카드 줄 아래 우측 하단의 위 chevron을 누르면 접힌 홈으로 돌아간다. 전체 프레임 1000×780, 콘텐츠 폭 840px를 유지한다.

| 연결 | 동작 | 전환 |
|---|---|---|
| 아래 chevron `181:1074` → `84:584` | 클릭 시 기간 카드가 캘린더 위로 펼쳐짐 | Smart Animate · ease-out · 220ms |
| 위 chevron `181:1083` → `84:467` | 클릭 시 기간 카드 접힘 | Smart Animate · ease-out · 220ms |

진행 막대는 실제 기간의 경과/상태를 뜻하므로 모션 대상이 아니다. 앱에서는 아이콘 손잡이를 키보드로 조작할 수 있는 버튼으로 구현하고 화면에 보이지 않는 접근성 이름과 `aria-expanded`·`aria-controls`를 제공한다. 시각적 손잡이보다 충분한 클릭 영역을 확보하고, OS의 reduced-motion 설정에서는 전환을 끄거나 줄인다. 펼침에 의해 가려진 캘린더 버튼이 포커스를 받지 않도록 처리하며 기존 Escape·바깥 클릭·초점 복귀 계약을 유지한다.

하위 할 일도 미완료 그룹이 먼저, 완료 그룹이 목록의 가장 뒤에 묶여 보인다. 각 그룹 안의 기존 순서를 유지하며 새로 완료한 항목은 완료 그룹의 마지막으로, 완료를 해제한 항목은 미완료 그룹의 마지막으로 이동하는 동작 계약이다. 항목 ID·연결·저장값은 보존하고 표시 순서 때문에 항목을 삭제하거나 새로 생성하지 않는다. Figma 상세 `133:22379`에는 미완료 두 개 뒤에 완료 두 개와 기존 2/4 요약을 표시했다.

Figma 프레젠테이션에서 화살표 왕복 전환과 캘린더를 덮는 배치를 확인했다. 하위 항목은 정렬된 시각 상태만 반영했으며 실제 체크에 따른 자동 이동, 앱 구현·키보드·저장 검증은 남아 있다. 변경 전·후 증거와 레퍼런스는 [최신 감사 항목](ui-audit/current-2026-10-06/audit.md#2026-10-07-우측-하단-펼침캘린더-오버레이완료-하위-항목)을 참조한다.

## 최신 사용자 지시: 원본 페이지를 기준으로 다시 구성

2026-10-06에 기준을 [Figma `0:1` · 01 · 홈 — 월간 할 일](https://www.figma.com/design/o81oyODBLYZuzBAkKcWqgp/TodoList?node-id=0-1)로 전환했다. computer use로 삭제 전 버전을 저장하고 다른 두 페이지(`Desktop Refined / Components`, `03 · Compact Desktop Screens`)를 삭제했으며, 단일 페이지가 남았음을 UI와 Figma metadata에서 확인했다. [정리 결과 캡처](ui-audit/current-2026-10-06/29-figma-only-source-page.jpg)를 보존했다.

원본 페이지의 1440×930 홈·기간 카드·펼침 상태를 직접 캡처하고, `product-design:ideate`로 원본을 참조한 세 시안을 생성했다. 이후 사용자가 `84:467`의 3개 기간 카드 홈과 `84:584`의 펼침 홈만 남겼으므로 이 두 화면으로 기준이 확정되었다. 전체 프레임은 1000×780, 콘텐츠 폭은 840px로 조정한다. 최신 요청은 같은 페이지에 주간 달력·사용자 화면·생성 팝업을 Apple 스타일로 설계하는 것이다. Figma 설계와 앱 구현은 별도로 기록한다.

기존 수정 작업 트리와 저장·편집·날짜/시각·countdown·하위 일·완료·시간대/DST·알림·메모·링크 및 키보드 동작 계약은 유지한다. 생성 이미지나 Figma 시안은 구현 완료 또는 실제 저장 동작의 검증 증거로 취급하지 않는다.

아래 `114:*` 프레임 기준의 정렬·검증 결과는 전환 전 이력이다. 해당 프레임이 있던 페이지는 사용자 지시로 삭제했으므로 새 구현의 기준 링크로 사용하지 않는다. 현행 기준과 시안 증거는 [최신 감사](ui-audit/current-2026-10-06/audit.md#현재-기준-원본-홈-페이지로-전환)를 따른다.

## 2026-10-07 사용자 수정 요청: 할 일 생성 흐름

다음 계약이 아래 초기 Apple 시안의 할 일 날짜 입력 및 부모 안에서의 하위 항목 추가 방식보다 우선한다. 사용자 재개 지시 후 computer use로 Figma 화면에 반영했다. 앱 저장 구조와 실제 입력 동작의 전환은 후속 구현으로 남아 있다.

| 대상 | 수정할 동작 | 유지할 동작 / 확인할 부분 |
|---|---|---|
| 새 할 일의 날짜 | 달력에서 선택한 날짜를 생성 시 그대로 사용한다. 팝업에는 `10월 6일 화요일`처럼 읽기 전용 날짜 맥락을 표시하고 날짜 입력·날짜 미정 토글을 제거한다. | 이 요청은 생성 흐름에 적용한다. 기존 항목의 저장 날짜를 바꾸거나 기존 날짜 미정 데이터를 삭제하지 않는다. 일정과 기간의 시작/종료 날짜·시각 입력은 유지한다. |
| 새 할 일의 상위 항목 | 이름 아래에 선택적인 `상위 항목` 선택 입력을 둔다. `없음`을 선택하면 독립 할 일로 생성한다. | 이번 설계는 기존 기간제 일정(window/deadline)을 우선 후보로 삼는다. 기존 할 일의 다단계 부모 관계는 추가하지 않았다. 선택지 시안은 없음·논문 초안 제출·학회 등록 기간·수강신청 본신청이다. |
| 상위 항목 안의 하위 항목 | 상세의 하위 항목 추가 입력과 `+ 하위 할 일 추가` 버튼을 제거한다. 새 할 일 생성에서 상위 항목을 선택해 연결한다. | 4개 예시 항목·체크박스·2/4 완료 요약·기간 자체 완료를 유지한다. 각 행의 `열기`는 개별 할 일 편집 진입 의도다. 기존 데이터와 편집값을 지우지 않는다. |
| 폼과 키보드 | 이름 → 상위 항목 → 완료 → 추가 설정 → 취소/저장 순서로 간결하게 배치한다. | 최초 이름 포커스, Tab 순환, Escape·취소·변경 폐기 확인·저장·호출 버튼 포커스 복귀를 유지한다. |

현재 앱의 `TaskItem`에는 부모 참조가 없고 기간의 `checklist`는 `{ id, title, completed }`를 부모 내부에 저장한다. 따라서 하위 항목 추가 UI만 먼저 없애면 새 하위 항목을 만들 경로가 사라진다. 후속 구현은 상위 항목 선택·저장·수정 경로를 갖춘 뒤 기존 체크리스트를 보존하는 방식으로 전환해야 한다. Firebase 변경은 이번 범위에 포함하지 않는다.

처음에는 Figma 접근 자동 승인 검토의 네트워크 연결 오류로 편집이 실행되지 않았다. 사용자 `진행` 지시 후 접근을 재시도해 복구했고, 동일 원본 페이지의 새 할 일 `133:21308`, 두 기간 기본 폼 `133:21799`/`133:22089`, 상세 `133:22379`를 수정했다. 상위 항목 선택 펼침 상태는 [155:960](https://www.figma.com/design/o81oyODBLYZuzBAkKcWqgp/TodoList?node-id=155-960)에 추가했다. 기존 루트 ID와 위치를 유지했다.

새 할 일 모달은 `(280,165) 440×450`이며 고정 제목 90px·본문 286px·푸터 72px다. 상위 항목 입력은 392px 폭이다. 기간 기본 폼의 접힘 제목은 `연결된 할 일 · 완료`, 새 기간 예시 요약은 `0개 · 미완료`로 변경했다. 상세 모달은 440×740과 본문 viewport 580px를 유지하고 추가 버튼 공간을 제거해 실제 본문 높이를 1115→1079px로 줄였다. 완료·시간대/DST·알림·메모·링크는 유지했다. 새 할 일과 상세 metadata에 텍스트·인스턴스·프레임이 남아 있고 이미지 노드는 없다.

변경 전후 1000×780 증거는 [49 · 변경 전](ui-audit/current-2026-10-06/49-before-task-parent-flow-1000x780.png), [50 · 변경 후](ui-audit/current-2026-10-06/50-after-task-parent-flow-1000x780.png), [51 · 상위 항목 선택](ui-audit/current-2026-10-06/51-parent-selection-1000x780.png), [54 · 연결된 할 일 상세](ui-audit/current-2026-10-06/54-advanced-linked-tasks-1000x780.png)에 저장했다. 시안의 10월 6일은 선택 날짜 예시이며 현재 날짜를 자동 계산한 동작 증거가 아니다. 선택·저장·키보드 동작은 아직 프로토타입이나 앱에서 연결·검증하지 않았다.

상위 항목 팝오버가 저장 버튼을 덮던 부분은 392×121·30px 옵션 행으로 수정했다. 상세는 [56 · 위](ui-audit/current-2026-10-06/56-linked-tasks-advanced-top-1000x780.jpg)와 [57 · 아래](ui-audit/current-2026-10-06/57-linked-tasks-advanced-bottom-1000x780.jpg)에서 실제 본문 스크롤과 고정 제목/푸터를 확인했다. 잘림과 버튼 겹침 없이 메모·링크까지 접근한다. 이 검수는 Figma의 본문 세로 스크롤에 한정된다.

## Apple 스타일 추가 화면의 동작 설계 · 수정 요청 전 시안

같은 원본 페이지에 주간 달력·사용자·추가 메뉴·새 할 일·새 일정·선착순 신청·기간 내 할 일·기간 상세의 8개 편집 가능한 Figma 화면을 추가했다. 모두 1000×780, 콘텐츠 폭 840px이며 모달 폭은 440px다. 기본 할 일/일정은 490px 높이, 기본 기간 두 유형은 550px, 상세 확장은 최대 740px다. 현행 프레임 링크·1000×780 캡처·레이어 수정 결과는 [최신 감사의 추가 화면 목록](ui-audit/current-2026-10-06/audit.md#apple-스타일-추가-화면--figma-설계)에 기록한다.

| 화면 / 조작 | 새 설계의 의도 | 후속 구현에서 유지할 계약 |
|---|---|---|
| 하단 가운데 / 오른쪽 | 주간 달력 / 사용자 화면 | 기존 route 이동, 아이콘 접근성 이름·포커스 유지 |
| 주간 날짜·시간표 | 오늘·주 이동, 종일/기간 칩과 시간 일정 분리, 겹친 일정 2열 | 실제 날짜/요일 계산, 빈 슬롯 날짜·시각 prefill, 08…22시 전체 시간 접근 |
| 햄버거 | 새 할 일·새 일정·선착순 신청·기간 내 할 일 4개 | 각 유형에 맞는 생성 폼, 방향키·Escape·바깥 클릭·초점 복귀 |
| 기본 생성 팝업 | 이름·날짜·시각과 필요한 상태를 먼저 표시 | 기존 유효성 검사·저장·수정, 날짜 미정/종일/선택 시작·종료 동작 |
| 기간 유형 | 햄버거에서 선택한 유형을 제목과 고정 안내로 표시 | 입력 안에서 다른 유형으로 전환하지 않음 |
| 하위 할 일 · 완료 | 접힌 영역에서 펼침, 4개 예시·추가/삭제·완료·전체 완료 | 입력 개수 제한을 새로 만들지 않음, 편집값과 dirty 상태 유지 |
| 추가 설정 | 시간대/DST·알림·메모·링크를 단계적으로 노출 | 접힌 입력값과 기존 저장값 유지, 오류가 난 영역 자동 펼침 |
| 상세 팝업 | 제목과 저장/취소 고정, 긴 본문만 스크롤 | 이중 스크롤·문서 가로 overflow·버튼 겹침 방지, 숨긴 입력은 Tab 순환에서 제외 |
| 취소 / 닫기 / Escape / 저장 | 모든 팝업의 같은 위치와 시각 계층 | 변경 폐기 확인, 최초 제목 포커스, 호출 요소 복귀, 실제 저장 처리 유지 |
| 사용자 설정 | 프로필·계정, 일정/알림, 데이터 관리의 얇은 구분선 그룹 | 기존 로그인 모드별 계정 기능과 로컬 백업/복원 기능에 맞춰 제공 |

상세 본문과 주간 시간표에는 Figma UI에서 세로 오버플로를 설정했다. 1000×780 브라우저에서 실제 휠 스크롤로 상세 이름/날짜부터 메모/링크까지, 주간 08시부터 22시까지 도달하며 제목·푸터/날짜·ICS·탐색이 고정됨을 확인했다. 전후 캡처는 [최신 감사의 스크롤 검수](ui-audit/current-2026-10-06/audit.md#figma-본문-스크롤-검수)에 기록했다. DST 상세는 America/New_York의 2026-11-01 01:30 중복 시각을 선택하는 실제 입력 예시로 맞췄다.

이는 동작 계약을 담은 화면 설계이며 화면 간 이동·저장 프로토타입 연결 또는 앱 반영 완료를 뜻하지 않는다. 현재 앱 작업 트리와 이전 검증 결과를 보존했다. 계정·Firebase 작업은 별도 범위다.

설계 작업 뒤 `pnpm typecheck`, `pnpm lint`를 다시 실행해 통과했다. `pnpm test`의 unit 213개는 통과했지만 Java runtime 부재로 Emulator 시작에서 중단되어 전체 테스트는 통과하지 못했다. 3001 프리뷰는 HTTP 200이며 계속 켜 두었다. Figma 스크롤 검수와 프로젝트 테스트 결과는 서로 별개의 증거다.

### 후속 반영: 간결한 기간 입력과 주간 캘린더

원본 Figma를 다시 확인한 뒤 기간 입력은 560×702에서 기본 신청 440×463, 기본 마감 440×393으로 줄였다. Figma 구성요소 폭 440px, 필드 410×34, 패널 모서리 14px, 버튼 72×30을 적용했다. 제목·날짜/시각·선택 시작/종료·시작 countdown을 먼저 보이고, 하위 할 일·완료와 시간대·알림·메모·링크·분류는 두 펼침 영역에서 편집한다. 접힌 필드의 입력과 기존 저장값은 유지된다. 오류가 있으면 해당 영역을 자동으로 연다.

본문만 길이에 따라 스크롤하며 제목·닫기와 저장·취소는 고정된다. 기본 폼에는 스크롤이 없고 전체 확장 상태는 최대 440×740이다. 1000×780과 390×844에서 본문/버튼 겹침, 문서 가로 overflow, 이중 다이얼로그 스크롤 없이 확인했다. 최초 제목 포커스, 숨겨진 입력을 제외한 Tab 순환, Escape·취소·폐기 확인, 호출 버튼 복귀를 검수했다. 체크리스트 삭제도 dirty 상태로 처리하며 햄버거에서 연 유형은 고정한다.

[주간 Figma 114:1698](https://www.figma.com/design/o81oyODBLYZuzBAkKcWqgp?node-id=114-1698)에 따라 이전/다음/오늘을 제목 옆에, 기간/햄버거를 오른쪽에 정렬했다. 날짜 열과 종일 칩의 간격, 라벤더 색, ICS 버튼 위치·크기를 맞췄다. 로딩바처럼 보이던 박스는 실제 기간 span으로 확인되어 기간 범위를 보존한 22px 칩으로 정리했다. 겹치는 기간과 하루 task는 행을 나누므로 실제 두 행 fixture는 단일행 원본보다 grid/ICS가 8px 아래에 놓인다. 08–22시 전체 시간은 306px viewport 안에서 스크롤하고 키보드 End/Home으로 접근한다. 빈 슬롯 prefill과 기간 전환을 유지하며, 캘린더에서 제목만 수정할 때 기존 알림 offset이 지워지던 문제를 고쳤다.

후속 비교 증거와 측정값은 [최신 감사](ui-audit/current-2026-10-06/audit.md#기간-입력주간-캘린더-후속-검수)에 기록했다. ### 남은 차이

Figma 입력은 440×304의 최소 예시이며 구현에는 모드·countdown 조절·펼침 버튼·닫기가 있어 높이가 더 크다. 원본 주간의 범위/날짜/요일, 이벤트 시각과 위치, 그리드 밖 시간 라벨은 서로 불일치하므로 구현은 실제 날짜·시각 계산을 따른다. computer use로 원본 사이트를 확인했지만 연결 실패와 미동기화 변경 안내가 표시되어 저장 완료를 검증할 수 없다. 원본은 수정하지 않았으며, 해당 날짜/요일/위치 정정은 연결 복구 뒤 남은 작업이다.

## 구현 문서 자체 검토

이 문서와 [07 컴포넌트 시스템](07-component-system-design.md), [08 데스크톱 구현 계획](08-desktop-ui-implementation-plan.md), [구성요소 매핑](component-mapping.md)을 다시 대조한 결과:

- 홈은 월간 하루 할 일 화면이고 주간 시간 캘린더는 별도 route다.
- 기간은 최대 3개만 홈 상단에 고정하며 overflow는 화면을 밀지 않고 덮는다. 화살표는 Figma SVG다.
- 체크박스는 홈의 하루 할 일에만 있고, 기간 카드에는 추가 체크박스를 넣지 않는다. 기간 완료는 checklist와 별도다.
- 기간 시작일/끝은 bar 양 끝, 진행 전 안내는 시작 countdown 하나로 표현한다.
- 하단 탐색은 중앙 정렬된 아이콘만 표시한다. 화면 이름·검색 헤더를 다시 만들지 않는다.
- 창 크기 기준은 `1000×780`, 앱 프레임은 최대 `840×780`; 커지는 창에는 바깥 흰 공간만 늘어난다.
- 로컬 CRUD/순서/설정/ICS는 preview browser 저장에 머무르고 Firebase 연결은 이번 단계에서 제외한다.
- C-30은 별도 전역 토스트가 아니라 입력 화면의 인라인 라이브 상태로 구현한다. 성공 저장 뒤 편집 화면을 닫아 불필요한 확인 배너가 남지 않는다.

홈·상단 기간 카드·overlay·햄버거의 기존 정렬을 유지하고, 기간 입력과 주간 캘린더를 1000×780에서 변경 전후 캡처했다. 기간 입력의 추가 기능은 두 펼침 영역으로 보존했으며, 기존 마감 항목에도 선택 시작이 있으면 countdown을 지원하는 실제 계약을 문서에 바로잡았다. 데이터 저장·상태/기간 계산을 생략하거나 UI에서 대체하지 않았다.
